---
title: Démarrage rapide pour les marchands
description: Apportez de la liquidité au marché P2P. Enregistrez un portefeuille, déposez des jetons, autorisez Cosmos Pay à apparier les ordres, ajoutez des moyens d'encaissement, publiez des offres et gérez les ordres.
---

Un marchand détient des jetons dans le contrat du marché et échange avec les personnes que Cosmos Pay
apparie à ses offres. Les jetons restent sous le contrôle de votre portefeuille : Cosmos Pay prépare
chaque transaction et votre portefeuille la signe. Le tableau de bord fait chaque étape de cette page
sous **P2P**, dans la barre latérale ; vous voyez ici aussi les appels à l'API.

Chaque requête porte votre clé API avec la portée `p2p:write` :

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

## 1. Enregistrez un portefeuille

Un portefeuille se prouve par une signature EIP-191 sur un défi à usage unique. Demandez le défi,
signez son `message` avec `personal_sign` dans le portefeuille, puis enregistrez l'adresse avec la
signature. Le défi dure 10 minutes et ne sert qu'une fois.

```bash
curl -X POST $API/accounts/challenge -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet" }'
# → { "message": "…", "expiresAt": "…" }

curl -X POST $API/accounts -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet", "signature": "0x…", "label": "Treasury", "displayName": "Lumio Exchange" }'
```

Une adresse appartient à une seule organisation. Le `displayName` fait du portefeuille un marchand :
c'est ce que les acheteurs et les vendeurs voient sur leur cotation. Votre adresse n'y apparaît jamais.

## 2. Gérez le profil de marchand

```bash
curl -X PATCH $API/accounts/ACCOUNT_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "displayName": "Lumio Exchange", "merchantStatus": "PAUSED" }'
```

`merchantStatus` vaut `ACTIVE` ou `PAUSED`. Un marchand en pause ne reçoit plus de nouveaux ordres ;
les ordres déjà ouverts suivent leur cours. Chaque compte renvoie ses `stats` : `completedOrders`,
`cancelledOrders`, `completionRate`, `disputesLost` et `medianReleaseSeconds`.

## 3. Déposez de la liquidité

Les dépôts alimentent votre solde libre dans le contrat. Deux transactions : un `approve` du montant
exact, puis le `deposit`. Les montants sont en unités de base du jeton : avec 6 décimales,
`"5000000000"` vaut 5 000 USDC. Le générateur de transactions renvoie chacune non signée :

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "approve", "args": { "token": "USDC", "amount": "5000000000" } }'
# → { "chainId": 8453, "to": "0x…", "data": "0x…", "value": "0", "description": "Allow the P2P market to take exactly 5000 USDC" }
```

Envoyez-la depuis votre portefeuille, attendez sa confirmation, puis recommencez avec
`"action": "deposit"`. Le `network` est l'un des identifiants que liste `GET /v1/p2p/market`, et
`token` un symbole ou une adresse de contrat qui y figure. `withdraw` prend les mêmes arguments et
renvoie à tout moment des jetons libres vers votre portefeuille.

`GET /v1/p2p/accounts/{id}` lit le contrat en direct : pour chaque réseau et chaque jeton, l'`amount`
libre et le montant `locked` dans les ordres en cours, tous deux en unités de base, puis les conditions
du matcher que vous avez fixées et les bots que vous avez autorisés. Le montant libre est lu dans le
contrat ; `locked` est compté à partir des ordres ouverts via cette API.

## 4. Autorisez Cosmos Pay avec un plafond par ordre

Le matcher de Cosmos Pay ouvre des achats sur votre solde. Vous décidez du montant maximal qu'un
ordre peut bloquer, en unités de base :

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setMatcher", "args": { "maxPerOrder": "1000000000", "autoSettle": false } }'
```

Un plafond de `"0"` révoque l'autorisation, et un compte dont `matcher.maxPerOrder` vaut `"0"` n'est
pas autorisé sur ce réseau. Le matcher ne peut bloquer vos jetons que dans des ordres jusqu'à ce
plafond. Il ne peut ni les retirer ni les envoyer ailleurs.

<Callout type="warn" title="Laissez le règlement automatique désactivé">
Le règlement automatique permet de libérer un ordre que vous avez vendu après la fenêtre de
règlement si vous ne le contestez pas à temps. Un marchand de liquidité n'en a jamais besoin, et
l'API le refuse pour un portefeuille qui a des offres de vente actives. Libérez chaque ordre
vous-même ou avec votre bot.
</Callout>

## 5. Ajoutez des moyens d'encaissement

Un moyen d'encaissement est le compte sur lequel les acheteurs virent. Ses données sont stockées
chiffrées et ne sont montrées qu'à l'acheteur de chaque ordre. Ajoutez-en un par moyen que vous proposez :

```bash
curl -X POST $API/payment-methods -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "currency": "ARS",
    "rail": "ar_bank_transfer",
    "holderName": "Lumio Exchange SRL",
    "details": { "alias": "lumio.pagos.ars", "cuit": "30714209879" },
    "label": "Main account"
  }'
```

La pièce d'identité du titulaire fait partie des `details` :

| Moyen | Devise | `details` |
| --- | --- | --- |
| `ar_bank_transfer` | ARS | Exactement un parmi `cbu` et `alias`, et le `cuit` du titulaire |
| `br_pix` | BRL | `keyType` (`cpf`, `cnpj`, `email`, `phone`, `evp`) et `key` |
| `mx_spei` | MXN | `clabe`, avec son chiffre de contrôle |
| `co_bank_transfer` | COP | `bank`, `accountType` (`savings`, `checking`), `accountNumber`, `documentType` (`CC`, `CE`, `NIT`, `PP`), `documentNumber` |
| `pe_bank_transfer` | PEN | `cci`, `documentType` (`DNI`, `CE`, `RUC`, `PP`), `documentNumber` |
| `cl_bank_transfer` | CLP | `bank`, `accountType` (`checking`, `vista`, `savings`), `accountNumber`, `rut` |

Le marché liste les moyens en vigueur et leurs champs pour chaque devise.

## 6. Publiez des offres

Une offre indique ce que vous échangez, à quel prix et entre quelles limites.

```bash
curl -X POST $API/offers -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "side": "SELL_TOKEN",
    "network": "base",
    "token": "USDC",
    "currency": "ARS",
    "rails": ["ar_bank_transfer"],
    "price": "1432.50",
    "priceTtlSeconds": 600,
    "minFiat": "10000",
    "maxFiat": "2500000"
  }'
```

- `SELL_TOKEN` vend des jetons à ceux qui achètent. Chacun de ses `rails` a besoin d'un moyen d'encaissement actif.
- `BUY_TOKEN` achète des jetons à ceux qui vendent, et aux versements des clients.
- `price` est en monnaie locale par jeton, jusqu'à 6 décimales. Le prix reste appariable pendant `priceTtlSeconds` après chaque mise à jour, 10 minutes par défaut, entre 30 secondes et un jour ; chaque offre renvoie `priceFresh`. Mettez-le à jour avec `PATCH /v1/p2p/offers/{id}` ou laissez votre bot le faire.
- `minFiat` et `maxFiat` sont le plus petit et le plus gros ordre en monnaie locale.

Une offre est appariée lorsque votre statut de marchand est `ACTIVE`, que son prix est à jour et que
le montant entre dans ses limites. Un achat exige aussi un solde libre et un plafond par ordre au
moins égaux au montant en jetons ; une vente exige un solde libre qui couvre la caution. Parmi les
marchands éligibles, le meilleur prix pour la personne l'emporte, puis l'historique : taux d'ordres
aboutis, délai de libération et litiges perdus.

## 7. Gérez les ordres

`GET /v1/p2p/merchant/orders` liste les ordres appariés à vos portefeuilles, avec des filtres par
`status`, `kind` et `address`. Chacun renvoie `merchantSide`, votre côté, et ce dont vous avez besoin pour ce
côté : le nom et le document du `payer` pour un achat, le compte du `beneficiary` pour une vente ou
un versement.

| Ordre | Votre rôle | Ce que vous faites |
| --- | --- | --- |
| Achat ou encaissement | Vous vendez des jetons | Vérifiez que le virement vient du payeur indiqué, pour le montant exact, puis `release`. |
| Vente ou versement | Vous achetez des jetons | `accept` avant `acceptDeadline`, virez l'argent au bénéficiaire, puis `markPaid` avant `paymentDeadline`. |

Chaque action est une transaction du même générateur, signée dans votre portefeuille :

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "release", "args": { "orderId": "ORDER_ID" } }'
```

`cancel` refuse une vente ou un versement avant que vous ne payiez, et `dispute` demande à l'arbitre de trancher un ordre payé : en tant qu'acheteur d'une vente ou d'un
versement, à tout moment ; en tant que vendeur, seulement avant le `settleDeadline` de l'ordre. Ne libérez jamais un achat avant que l'argent soit sur votre compte, et
n'acceptez jamais un virement d'une autre personne que le payeur indiqué.
