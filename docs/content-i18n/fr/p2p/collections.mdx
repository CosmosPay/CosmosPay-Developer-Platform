title: Encaissements

---

Il existe deux façons d'encaisser avec le marché P2P. Un **encaissement** est un lien que vous
partagez : le payeur vire de la monnaie locale et vous recevez des stablecoins dans votre
portefeuille. La **rampe intégrée** place ce même parcours dans votre application, pour que vos
utilisateurs achètent et vendent.

## Encaissements

Créez un encaissement avec le montant en monnaie locale et le portefeuille enregistré qui reçoit les jetons :

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/charges \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "currency": "ARS",
    "fiatAmount": "85000",
    "network": "base",
    "token": "USDC",
    "recipient": "ACCOUNT_ID",
    "description": "Order #1042",
    "expiresAt": "2026-12-01T00:00:00Z",
    "multiUse": false
  }'
# → { "id": "…", "url": "https://payments.cosmospay.lat/p2p/…", "status": "open", "recipientAddress": "0x…", "paidCount": 0, … }
```

`recipient` est l'un de vos identifiants de compte. Un encaissement expire 24 heures après sa
création, sauf si `expiresAt` en décide autrement, au plus tard 30 jours après.

Partagez l'`url` en lien ; elle ouvre la page du payeur. Sur cette page, le payeur :

1. Voit le montant en monnaie locale.
2. Saisit son nom, sa pièce d'identité et son email. Le marchand vérifie que le virement vient de cette personne.
3. Obtient le compte du marchand et le montant exact, avec un compte à rebours pour le délai de paiement.
4. Vire depuis sa banque et appuie sur **J'ai viré**.
5. Suit le statut en direct jusqu'à ce que le marchand libère, puis voit le reçu.

Les jetons arrivent dans le portefeuille destinataire. Chaque fois qu'un ordre qui le paie aboutit,
l'encaissement envoie `P2P_CHARGE_SUCCEEDED` et le compte dans `paidCount`. Un encaissement accepte
un payeur à la fois ; activez `multiUse` pour encaisser plusieurs payeurs avec le même lien.
`status` vaut `open`, `paid`, `cancelled` ou `expired`. `DELETE /v1/p2p/charges/{id}` annule un
encaissement ouvert : aucun nouveau payeur ne peut commencer, et un ordre déjà en cours paie quand
même le destinataire quand il aboutit. Toutes les routes des encaissements figurent dans la
[référence des encaissements et versements](/api/p2p-collections/).

La page hébergée appelle les routes sans clé de l'[API de checkout P2P](/api/p2p-checkout/) : elle lit
l'encaissement, commence à le payer avec `POST /v1/p2p-checkout/charges/{id}/orders` et le moyen, le
nom, le document et l'email du payeur, et suit l'ordre avec le `payerToken` que porte cette réponse,
envoyé en `X-Payer-Token`.

## Rampe intégrée

Laissez vos utilisateurs acheter et vendre des stablecoins sans quitter votre application. Votre
serveur conserve la clé API ; le portefeuille de votre utilisateur ne signe que ce qu'il envoie.

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

### Acheter

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "BUY", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "fiatAmount": "50000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "recipient": "0xUserWallet",
    "payer": { "name": "Ana Gómez", "document": "20329642330" },
    "externalReference": "order-881"
  }'
```

L'ordre renvoie `paymentDetails`, le compte du marchand pour cet ordre, et `paymentDeadline`.
Montrez-les à votre utilisateur. Une fois le virement fait, signalez-le :

```bash
curl -X POST $API/orders/ORDER_ID/paid -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "reference": "TRX-88421" }'
```

Le nom et le document du payeur sont obligatoires : le marchand ne libère qu'un virement de cette
personne. `POST /v1/p2p/orders/{id}/cancel` annule avant le virement, et `/dispute` demande à
l'arbitre de trancher un ordre payé que le marchand ne libère pas.

Pour prélever vos propres frais, passez `integratorFeeBps` et `integratorAccountId` dans la
cotation. Ils sont prélevés sur ce que reçoit l'acheteur et versés sur la chaîne à ce portefeuille.

### Vendre

Le montant en jetons d'une vente est en unités de base : `"25000000"` vaut 25 USDC.

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "SELL", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "tokenAmount": "25000000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "seller": "0xUserWallet",
    "beneficiary": { "holderName": "Ana Gómez", "document": "20329642330", "details": { "alias": "ana.gomez.mp", "cuit": "20329642330" } }
  }'
```

L'ordre renvoie `transactions` : un `approve` et un `openWithDeposit`, non signés. Le portefeuille de
votre utilisateur envoie les deux, dans cet ordre. Le marchand accepte, vire l'argent sur le compte
du `beneficiary` et marque l'ordre comme payé. Votre utilisateur libère ensuite avec une transaction
`release` du générateur, avec son adresse en `from`. Si personne ne conteste l'ordre, n'importe qui
peut le libérer une fois la fenêtre de règlement écoulée.

`GET /v1/p2p/orders` liste les ordres que vous avez ouverts, avec des filtres par `status` et `kind`.
Leurs webhooks atteignent vos endpoints avec `role: "client"`.
