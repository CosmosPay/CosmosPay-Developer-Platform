---
title: Webhooks P2P
description: Los eventos que envían las órdenes, los cobros y los pagos a terceros P2P, quién recibe cada uno y qué contiene su payload.
---

Los eventos P2P pasan por los mismos endpoints de webhook que todos los eventos de Cosmos Pay, y se
firman de la misma manera. Registra un endpoint en el panel, en **Webhooks**, o con la API, y elige
los eventos de abajo.

## Eventos

| Evento | Se envía cuando |
| --- | --- |
| `P2P_ORDER_CREATED` | Una orden se abrió en cadena. |
| `P2P_ORDER_ACCEPTED` | Una orden espera el pago: un comerciante aceptó una venta o un pago a terceros, o se abrió una compra. |
| `P2P_ORDER_PAID` | El lado comprador marcó la orden como pagada. |
| `P2P_ORDER_COMPLETED` | El vendedor liberó. El comprador recibió los tokens. |
| `P2P_ORDER_CANCELLED` | La orden se canceló. Los tokens volvieron al vendedor. |
| `P2P_ORDER_EXPIRED` | Venció un plazo. Los tokens volvieron al vendedor. |
| `P2P_ORDER_DISPUTED` | Una de las partes abrió una disputa. |
| `P2P_ORDER_RESOLVED` | El árbitro resolvió la disputa. |
| `P2P_ORDER_FAILED` | La orden nunca se abrió. |
| `P2P_CHARGE_SUCCEEDED` | Se completó una orden que paga un cobro. Un cobro de uso múltiple envía uno por cada orden que lo paga. |
| `P2P_PAYOUT_BATCH_COMPLETED` | Terminaron todas las órdenes de un lote de pagos a terceros. |

Las órdenes completadas, canceladas, vencidas, resueltas y fallidas, los cobros exitosos y los lotes
terminados son finales: después no llega ningún otro evento.

## Quién los recibe

Los eventos de una orden llegan a dos partes: el cliente que la abrió y el comerciante con el que se
emparejó, cuando son organizaciones distintas. `data.role` indica cuál eres, y cada parte recibe solo
su propia vista de la orden.

| `data.role` | El payload contiene | Nunca contiene |
| --- | --- | --- |
| `client` | Los montos, las direcciones, los plazos, los hashes de las transacciones y el estado de la orden, el nombre visible y el historial del comerciante, y tus propios `externalReference`, `chargeId` y `payoutBatchId` | Datos de pago, la identidad del pagador ni la cuenta de un beneficiario |
| `merchant` | Los montos, las direcciones, los plazos, los hashes de las transacciones y el estado de la orden, con tus `merchantAccountId` y `merchantSide` | Datos de pago, la identidad del pagador, la cuenta de un beneficiario ni las referencias propias del cliente |

Lee la orden con la API para lo que un webhook deja afuera: `GET /v1/p2p/orders/{id}` como cliente,
`GET /v1/p2p/merchant/orders/{id}` como comerciante.

## Payload

```json
{
  "id": "evt_01JD6Q…",
  "type": "P2P_ORDER_PAID",
  "createdAt": "2026-11-19T14:02:11.000Z",
  "data": {
    "role": "merchant",
    "id": "3f1c2b7e-8d4a-4c1e-9b2f-6a5d4c3b2a10",
    "kind": "BUY",
    "status": "paid",
    "network": "base",
    "chainId": 8453,
    "merchantSide": "seller",
    "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
    "tokenSymbol": "USDC",
    "tokenDecimals": 6,
    "currency": "ARS",
    "rail": "ar_bank_transfer",
    "fiatAmount": "150000.00",
    "tokenAmount": "104712041",
    "netAmount": "104397905",
    "paymentDeadline": "2026-11-19T14:30:02.000Z",
    "paidReference": "TRX-88421"
  }
}
```

Usa `id` para procesar cada evento una sola vez. Vuelve a leer la orden con la API antes de mover
dinero: un evento te dice que algo cambió; la orden te dice cómo está ahora.

## Verifica la firma

Cada entrega lleva `X-Cosmos-Signature: t=<unix seconds>,v1=<hex>`, un HMAC-SHA256 de
`<t>.<raw body>` con el secreto de tu endpoint. Verifícalo sobre el cuerpo sin procesar antes de
confiar en el evento. El SDK lo hace por ti: consulta [Webhooks](/sdk/server/webhooks/).
