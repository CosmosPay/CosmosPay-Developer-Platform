---
title: Inicio rápido para comerciantes
description: Aporta liquidez al mercado P2P. Registra una billetera, deposita tokens, autoriza a Cosmos Pay a emparejar órdenes, agrega medios de cobro, publica ofertas y gestiona órdenes.
---

Un comerciante tiene tokens en el contrato del mercado y opera con las personas que Cosmos Pay
empareja con sus ofertas. Los tokens siguen bajo el control de tu billetera: Cosmos Pay arma cada
transacción y tu billetera la firma. El panel hace cada paso de esta página en **P2P**, en la barra
lateral; aquí también verás las llamadas a la API.

Cada solicitud lleva tu clave de API con el alcance `p2p:write`:

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

## 1. Registra una billetera

Una billetera se demuestra con una firma EIP-191 sobre un desafío de un solo uso. Pide el desafío,
firma su `message` con `personal_sign` en la billetera y luego registra la dirección con la firma.
El desafío dura 10 minutos y sirve una sola vez.

```bash
curl -X POST $API/accounts/challenge -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet" }'
# → { "message": "…", "expiresAt": "…" }

curl -X POST $API/accounts -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet", "signature": "0x…", "label": "Treasury", "displayName": "Lumio Exchange" }'
```

Una dirección pertenece a una sola organización. El `displayName` convierte la billetera en
comerciante: es lo que compradores y vendedores ven en su cotización. Tu dirección nunca se muestra ahí.

## 2. Gestiona el perfil de comerciante

```bash
curl -X PATCH $API/accounts/ACCOUNT_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "displayName": "Lumio Exchange", "merchantStatus": "PAUSED" }'
```

`merchantStatus` es `ACTIVE` o `PAUSED`. Un comerciante en pausa no recibe órdenes nuevas; las
órdenes ya abiertas siguen su curso. Cada cuenta responde sus `stats`: `completedOrders`,
`cancelledOrders`, `completionRate`, `disputesLost` y `medianReleaseSeconds`.

## 3. Deposita liquidez

Los depósitos van a tu saldo libre en el contrato. Son dos transacciones: un `approve` por el monto
exacto y luego el `deposit`. Los montos van en las unidades base del token: con 6 decimales,
`"5000000000"` son 5.000 USDC. El generador de transacciones responde cada una sin firmar:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "approve", "args": { "token": "USDC", "amount": "5000000000" } }'
# → { "chainId": 8453, "to": "0x…", "data": "0x…", "value": "0", "description": "Allow the P2P market to take exactly 5000 USDC" }
```

Envíala desde tu billetera, espera a que se confirme y repite con `"action": "deposit"`. La
`network` es uno de los identificadores que lista `GET /v1/p2p/market`, y `token` es un símbolo o
una dirección de contrato que figura ahí. `withdraw` recibe los mismos argumentos y devuelve tokens
libres a tu billetera en cualquier momento.

`GET /v1/p2p/accounts/{id}` lee el contrato en vivo: para cada red, los `balances` libres en
unidades base, las condiciones del matcher que fijaste y los bots que autorizaste.

## 4. Autoriza a Cosmos Pay con un tope por orden

El matcher de Cosmos Pay abre compras sobre tu saldo. Tú decides cuánto puede bloquear una orden
como máximo, en unidades base:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setMatcher", "args": { "maxPerOrder": "1000000000", "autoSettle": false } }'
```

Un tope de `"0"` revoca la autorización, y una cuenta cuyo `matcher.maxPerOrder` dice `"0"` no está
autorizada en esa red. El matcher solo puede bloquear tus tokens en órdenes hasta ese tope. No puede
retirarlos ni enviarlos a ningún lado.

<Callout type="warn" title="Mantén la liquidación automática desactivada">
La liquidación automática permite que una orden que vendiste se libere pasada la ventana de
liquidación si no la disputas a tiempo. Un comerciante de liquidez nunca la necesita, y la API la
rechaza para una billetera con ofertas de venta activas. Libera cada orden tú mismo o con tu bot.
</Callout>

## 5. Agrega medios de cobro

Un medio de cobro es la cuenta a la que transfieren los compradores. Sus datos se guardan cifrados
y solo se muestran al comprador de cada orden. Agrega uno por cada medio que ofreces:

```bash
curl -X POST $API/payment-methods -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "currency": "ARS",
    "rail": "ar_bank_transfer",
    "holderName": "Lumio Exchange SRL",
    "details": { "alias": "lumio.pagos.ars", "cuit": "30714209879" },
    "label": "Main account"
  }'
```

El documento de identidad del titular es uno de los `details`:

| Medio | Moneda | `details` |
| --- | --- | --- |
| `ar_bank_transfer` | ARS | Exactamente uno entre `cbu` y `alias`, y el `cuit` del titular |
| `br_pix` | BRL | `keyType` (`cpf`, `cnpj`, `email`, `phone`, `evp`) y `key` |
| `mx_spei` | MXN | `clabe`, con su dígito verificador |
| `co_bank_transfer` | COP | `bank`, `accountType` (`savings`, `checking`), `accountNumber`, `documentType` (`CC`, `CE`, `NIT`, `PP`), `documentNumber` |
| `pe_bank_transfer` | PEN | `cci`, `documentType` (`DNI`, `CE`, `RUC`, `PP`), `documentNumber` |
| `cl_bank_transfer` | CLP | `bank`, `accountType` (`checking`, `vista`, `savings`), `accountNumber`, `rut` |

El mercado lista los medios vigentes y sus campos dentro de cada moneda.

## 6. Publica ofertas

Una oferta indica qué operas, a qué precio y entre qué límites.

```bash
curl -X POST $API/offers -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "side": "SELL_TOKEN",
    "network": "base",
    "token": "USDC",
    "currency": "ARS",
    "rails": ["ar_bank_transfer"],
    "price": "1432.50",
    "priceTtlSeconds": 600,
    "minFiat": "10000",
    "maxFiat": "2500000"
  }'
```

- `SELL_TOKEN` vende tokens a quienes compran. Cada uno de sus `rails` necesita un medio de cobro activo.
- `BUY_TOKEN` compra tokens a quienes venden y a los pagos a terceros de los clientes.
- `price` es moneda local por token, con hasta 6 decimales. El precio se puede emparejar durante `priceTtlSeconds` después de cada actualización, 10 minutos por defecto y entre 30 segundos y un día; cada oferta responde `priceFresh`. Actualízalo con `PATCH /v1/p2p/offers/{id}` o deja que lo haga tu bot.
- `minFiat` y `maxFiat` son la orden más chica y la más grande en moneda local.

Una oferta se empareja cuando tu estado de comerciante es `ACTIVE`, su precio está vigente y el
monto entra en sus límites. Una compra además necesita un saldo libre y un tope por orden de al
menos el monto en tokens; una venta necesita un saldo libre que cubra la garantía. Entre los
comerciantes que califican gana el mejor precio para la persona, y luego el historial: tasa de
órdenes completadas, tiempo de liberación y disputas perdidas.

## 7. Gestiona órdenes

`GET /v1/p2p/merchant/orders` lista las órdenes emparejadas con tus billeteras, con filtros por
`status` y `kind`. Cada una responde `merchantSide`, tu lado en ella, y lo que necesitas para ese
lado: el nombre y el documento del `payer` en una compra, la cuenta del `beneficiary` en una venta o
un pago a terceros.

| Orden | Tu rol | Qué haces |
| --- | --- | --- |
| Compra o cobro | Vendes tokens | Verifica que la transferencia llegó del pagador indicado, por el monto exacto, y luego `release`. |
| Venta o pago a terceros | Compras tokens | `accept` antes de `acceptDeadline`, transfiere el dinero al beneficiario y luego `markPaid` antes de `paymentDeadline`. |

Cada acción es una transacción del mismo generador, firmada en tu billetera:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "release", "args": { "orderId": "ORDER_ID" } }'
```

`cancel` rechaza una venta o un pago a terceros antes de que pagues, y `dispute` le pide al árbitro
que decida sobre una orden pagada. Nunca liberes una compra antes de tener el dinero en tu cuenta,
y nunca aceptes una transferencia de alguien distinto del pagador indicado.
