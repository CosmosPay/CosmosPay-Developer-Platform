---
title: Inicio rápido para comerciantes
description: Aporta liquidez al mercado P2P. Registra una billetera, deposita tokens, autoriza a Cosmos Pay a emparejar órdenes, agrega medios de cobro, publica ofertas y gestiona órdenes.
---

Un comerciante tiene tokens en el contrato del mercado y opera con las personas que Cosmos Pay
empareja con sus ofertas. Los tokens siguen bajo el control de tu billetera: Cosmos Pay arma cada
transacción y tu billetera la firma. El panel hace cada paso de esta página en **P2P**, en la barra
lateral; aquí también verás las llamadas a la API.

Cada solicitud lleva tu clave de API con el alcance `p2p:write`:

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

## 1. Registra una billetera

Una billetera se demuestra con una firma EIP-191 sobre un desafío de un solo uso. Pide el desafío,
firma su `message` con `personal_sign` en la billetera y luego regístrala.

```bash
curl -X POST $API/accounts/challenge -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet" }'
# → { "id": "…", "message": "Cosmos Pay wants you to register this wallet…", "expiresAt": "…" }

curl -X POST $API/accounts -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "challengeId": "…", "address": "0xYourWallet", "signature": "0x…", "label": "Treasury" }'
```

El desafío vence en minutos y sirve una sola vez. Una dirección pertenece a una sola organización.

## 2. Nómbrala como comerciante

El nombre visible es lo que compradores y vendedores ven en su cotización. Tu dirección nunca se muestra.

```bash
curl -X PATCH $API/accounts/ACCOUNT_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "merchant": { "displayName": "Lumio Exchange", "status": "ACTIVE" } }'
```

Usa `status` en `PAUSED` para dejar de recibir órdenes nuevas. Las órdenes ya abiertas siguen su curso.

## 3. Deposita liquidez

Los depósitos van a tu saldo libre en el contrato. Son dos transacciones: un `approve` por el monto
exacto y luego el `deposit`. El generador de transacciones responde cada una sin firmar:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "approve", "args": { "token": "USDC", "amount": "5000" } }'
# → { "chainId": 8453, "to": "0x…", "data": "0x…", "value": "0", "description": "…" }
```

Envíala desde tu billetera, espera a que se confirme y repite con `"action": "deposit"`. La
`network` es uno de los identificadores que lista `GET /v1/p2p/market`. `withdraw` recibe los mismos
argumentos y devuelve tokens libres a tu billetera en cualquier momento.

## 4. Autoriza a Cosmos Pay con un tope por orden

El matcher de Cosmos Pay abre compras sobre tu saldo. Tú decides cuánto puede bloquear una orden como máximo:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setMatcher", "args": { "maxPerOrder": "1000", "autoSettle": false } }'
```

Un tope de `0` revoca la autorización. El matcher solo puede bloquear tus tokens en órdenes hasta
ese tope. No puede retirarlos ni enviarlos a ningún lado.

<Callout type="warn" title="Mantén la liquidación automática desactivada">
La liquidación automática permite que una orden que vendiste se libere sola después de la ventana
de liquidación. Un comerciante de liquidez nunca la necesita, y la API la rechaza para una billetera
con ofertas de venta activas. Libera cada orden tú mismo o con tu bot.
</Callout>

## 5. Agrega medios de cobro

Un medio de cobro es la cuenta a la que transfieren los compradores. Se guarda cifrado y solo se
muestra al comprador de cada orden. Agrega uno por cada medio que ofreces:

```bash
curl -X POST $API/payment-methods -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "rail": "ar_bank_transfer",
    "label": "Main account",
    "holderName": "Lumio Exchange SRL",
    "document": "30714209879",
    "details": { "cbu": "0170099222000001234561", "alias": "lumio.pagos.ars" }
  }'
```

| Medio | Moneda | `details` | `document` del titular |
| --- | --- | --- | --- |
| `ar_bank_transfer` | ARS | `cbu` con sus dígitos verificadores, o `alias` | CUIT o CUIL |
| `br_pix` | BRL | `pixKeyType` (`cpf`, `cnpj`, `email`, `phone`, `evp`) y `pixKey` | CPF o CNPJ |
| `mx_spei` | MXN | `clabe` con su dígito verificador | RFC, opcional |
| `co_bank_transfer` | COP | `bank`, `accountType` (`savings`, `checking`), `accountNumber` | NIT o cédula |
| `pe_bank_transfer` | PEN | `cci` | DNI o RUC |
| `cl_bank_transfer` | CLP | `bank`, `accountType` (`checking`, `vista`, `savings`), `accountNumber` | RUT |

El mercado lista los medios vigentes y sus campos.

## 6. Publica ofertas

Una oferta indica qué operas, a qué precio y entre qué límites.

```bash
curl -X POST $API/offers -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "side": "SELL_TOKEN",
    "network": "base",
    "token": "USDC",
    "currency": "ARS",
    "rails": ["ar_bank_transfer"],
    "price": "1432.50",
    "priceTtlSeconds": 900,
    "minFiat": "10000",
    "maxFiat": "2500000"
  }'
```

- `SELL_TOKEN` vende tokens a quienes compran. Cada uno de sus `rails` necesita un medio de cobro activo.
- `BUY_TOKEN` compra tokens a quienes venden y a los pagos a terceros de los clientes.
- `price` es moneda local por token. Un precio más antiguo que `priceTtlSeconds` no se empareja: actualízalo con `PATCH /v1/p2p/offers/{id}` o deja que lo haga tu bot.

Una oferta se empareja cuando tu estado de comerciante es `ACTIVE`, su precio está vigente y el
monto entra en sus límites. Una compra además necesita un saldo libre y un tope por orden de al
menos el monto en tokens; una venta necesita un saldo libre que cubra la garantía. Entre los
comerciantes que califican gana el mejor precio para la persona, y luego el historial: tasa de
órdenes completadas, tiempo de liberación y disputas perdidas.

## 7. Gestiona órdenes

`GET /v1/p2p/merchant/orders` lista las órdenes emparejadas con tus billeteras. Cada una muestra lo
que necesitas para tu lado y nada más.

| Orden | Tu rol | Qué haces |
| --- | --- | --- |
| Compra o cobro | Vendes tokens | Verifica que la transferencia llegó del pagador que indica la orden, por el monto exacto, y luego `release`. |
| Venta o pago a terceros | Compras tokens | `accept` antes del plazo de aceptación, transfiere el dinero a la cuenta que muestra la orden y luego `markPaid`. |

Cada acción es una transacción del mismo generador, firmada en tu billetera:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "release", "args": { "orderId": "ORDER_ID" } }'
```

`cancel` rechaza una venta antes de que pagues, y `dispute` le pide al árbitro que decida sobre una
orden pagada. Nunca liberes una compra antes de tener el dinero en tu cuenta, y nunca aceptes una
transferencia de alguien distinto del pagador indicado.
