---
title: Webhooks P2P
description: Os eventos que ordens, cobranças e pagamentos a terceiros P2P enviam, quem recebe cada um e o que o payload contém.
---

Os eventos P2P passam pelos mesmos endpoints de webhook que todos os eventos da Cosmos Pay, assinados
da mesma forma. Registre um endpoint no painel, em **Webhooks**, ou pela API, e escolha os eventos
abaixo.

## Eventos

| Evento | Enviado quando |
| --- | --- |
| `P2P_ORDER_CREATED` | Uma ordem foi aberta on-chain. |
| `P2P_ORDER_ACCEPTED` | Uma ordem aguarda o pagamento: um comerciante aceitou uma venda ou um pagamento a terceiros, ou uma compra foi aberta. |
| `P2P_ORDER_PAID` | O lado comprador marcou a ordem como paga. |
| `P2P_ORDER_COMPLETED` | O vendedor liberou. O comprador recebeu os tokens. |
| `P2P_ORDER_CANCELLED` | A ordem foi cancelada. Os tokens voltaram ao vendedor. |
| `P2P_ORDER_EXPIRED` | Um prazo venceu. Os tokens voltaram ao vendedor. |
| `P2P_ORDER_DISPUTED` | Uma das partes abriu uma disputa. |
| `P2P_ORDER_RESOLVED` | O árbitro resolveu a disputa. |
| `P2P_ORDER_FAILED` | A ordem nunca foi aberta. |
| `P2P_CHARGE_SUCCEEDED` | Uma ordem que paga uma cobrança foi concluída. Uma cobrança de uso múltiplo envia um por ordem que a paga. |
| `P2P_PAYOUT_BATCH_COMPLETED` | Todas as ordens de um lote de pagamentos a terceiros terminaram. |

Ordens concluídas, canceladas, vencidas, resolvidas e que falharam, cobranças bem-sucedidas e lotes
terminados são finais: nenhum outro evento vem depois deles.

## Quem recebe

Os eventos de uma ordem chegam a duas partes: o cliente que a abriu e o comerciante com quem ela foi
combinada, quando são organizações diferentes. `data.role` diz qual delas você é, e cada parte
recebe apenas a própria visão da ordem.

| `data.role` | O payload contém | Nunca contém |
| --- | --- | --- |
| `client` | Os valores, os endereços, os prazos, os hashes das transações e o status da ordem, o nome de exibição e o histórico do comerciante, e seus próprios `externalReference`, `chargeId` e `payoutBatchId` | Dados de pagamento, a identidade do pagador ou a conta de um beneficiário |
| `merchant` | Os valores, os endereços, os prazos, os hashes das transações e o status da ordem, com seus `merchantAccountId` e `merchantSide` | Dados de pagamento, a identidade do pagador, a conta de um beneficiário ou as referências próprias do cliente |

Leia a ordem pela API para o que um webhook deixa de fora: `GET /v1/p2p/orders/{id}` como cliente,
`GET /v1/p2p/merchant/orders/{id}` como comerciante.

## Payload

```json
{
  "id": "evt_01JD6Q…",
  "type": "P2P_ORDER_PAID",
  "createdAt": "2026-11-19T14:02:11.000Z",
  "data": {
    "role": "merchant",
    "id": "3f1c2b7e-8d4a-4c1e-9b2f-6a5d4c3b2a10",
    "kind": "BUY",
    "status": "paid",
    "network": "base",
    "chainId": 8453,
    "merchantSide": "seller",
    "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
    "tokenSymbol": "USDC",
    "tokenDecimals": 6,
    "currency": "ARS",
    "rail": "ar_bank_transfer",
    "fiatAmount": "150000.00",
    "tokenAmount": "104712041",
    "netAmount": "104397905",
    "paymentDeadline": "2026-11-19T14:30:02.000Z",
    "paidReference": "TRX-88421"
  }
}
```

Use `id` para processar cada evento uma única vez. Leia a ordem de novo pela API antes de mexer em
dinheiro: um evento diz que algo mudou; a ordem diz como ela está agora.

## Verifique a assinatura

Cada entrega leva `X-Cosmos-Signature: t=<unix seconds>,v1=<hex>`, um HMAC-SHA256 de
`<t>.<raw body>` com o segredo do seu endpoint. Verifique sobre o corpo bruto antes de confiar no
evento. O SDK faz isso por você: veja [Webhooks](/sdk/server/webhooks/).
