title: Cobranças

---

Há duas formas de cobrar pelo mercado P2P. Uma **cobrança** é um link que você compartilha: o
pagador transfere moeda local e você recebe stablecoins na sua carteira. A **rampa integrada** leva o
mesmo fluxo para dentro do seu app, para que seus usuários comprem e vendam.

## Cobranças

Crie uma cobrança com o valor em moeda local e a carteira registrada que recebe os tokens:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/charges \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "currency": "ARS",
    "fiatAmount": "85000",
    "network": "base",
    "token": "USDC",
    "recipient": "ACCOUNT_ID",
    "description": "Order #1042",
    "expiresAt": "2026-12-01T00:00:00Z",
    "multiUse": false
  }'
# → { "id": "…", "url": "https://payments.cosmospay.lat/p2p/…", "status": "open", "recipientAddress": "0x…", "paidCount": 0, … }
```

`recipient` é um dos seus identificadores de conta. Uma cobrança expira 24 horas depois de criada,
a menos que `expiresAt` diga outra coisa, com no máximo 30 dias.

Compartilhe a `url`, como link ou como QR code; o painel desenha um para você. Nessa página, o pagador:

1. Vê o valor em moeda local.
2. Informa nome, documento de identidade e email. O comerciante confere se a transferência vem dessa pessoa.
3. Recebe a conta do comerciante e o valor exato, com uma contagem regressiva da janela de pagamento.
4. Transfere pelo banco e toca em **Já transferi**.
5. Acompanha o status ao vivo até o comerciante liberar e então vê o comprovante.

Os tokens chegam à carteira recebedora. Cada vez que uma ordem que a paga é concluída, a cobrança
envia `P2P_CHARGE_SUCCEEDED` e a conta em `paidCount`. Uma cobrança aceita um pagador por vez; ative
`multiUse` para receber de vários pagadores com o mesmo link. `status` é `open`, `paid`, `cancelled`
ou `expired`. `DELETE /v1/p2p/charges/{id}` cancela uma cobrança aberta: nenhum pagador novo pode
começar, e uma ordem já em andamento ainda paga o recebedor quando é concluída. Todas as rotas de cobranças estão na
[referência de cobranças e pagamentos a terceiros](/api/p2p-collections/).

A página hospedada chama as rotas sem chave da [API de checkout P2P](/api/p2p-checkout/): lê a
cobrança, começa a pagá-la com `POST /v1/p2p-checkout/charges/{id}/orders` e o meio, o nome, o
documento e o email do pagador, e acompanha a ordem com o `payerToken` que essa resposta traz,
enviado como `X-Payer-Token`.

## Rampa integrada

Permita que seus usuários comprem e vendam stablecoins sem sair do seu app. Seu servidor guarda a
chave de API; a carteira do seu usuário assina só o que ela envia.

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

### Comprar

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "BUY", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "fiatAmount": "50000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "recipient": "0xUserWallet",
    "payer": { "name": "Ana Gómez", "document": "20329642330" },
    "externalReference": "order-881"
  }'
```

A ordem responde `paymentDetails`, a conta do comerciante para esta ordem, e `paymentDeadline`.
Mostre-os ao seu usuário. Quando ele transferir, informe:

```bash
curl -X POST $API/orders/ORDER_ID/paid -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "reference": "TRX-88421" }'
```

O nome e o documento do pagador são obrigatórios: o comerciante libera apenas uma transferência
dessa pessoa. `POST /v1/p2p/orders/{id}/cancel` cancela antes da transferência, e `/dispute` pede ao
árbitro que decida sobre uma ordem paga que o comerciante não libera.

Para cobrar sua própria tarifa, envie `integratorFeeBps` e `integratorAccountId` na cotação. A tarifa
sai do que o comprador recebe e é paga on-chain para essa carteira.

### Vender

O valor em tokens de uma venda fica em unidades base: `"25000000"` são 25 USDC.

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "SELL", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "tokenAmount": "25000000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "seller": "0xUserWallet",
    "beneficiary": { "holderName": "Ana Gómez", "document": "20329642330", "details": { "alias": "ana.gomez.mp", "cuit": "20329642330" } }
  }'
```

A ordem responde `transactions`: um `approve` e um `openWithDeposit`, não assinados. A carteira do
seu usuário envia as duas, nessa ordem. O comerciante aceita, transfere o dinheiro para a conta do
`beneficiary` e marca a ordem como paga. Depois seu usuário libera com uma transação `release` do
gerador, com o endereço dele como `from`. Se ninguém disputar a ordem, qualquer pessoa pode
liberá-la depois que a janela de liquidação passar.

`GET /v1/p2p/orders` lista as ordens que você abriu, com filtros por `status` e `kind`. Os webhooks
delas chegam aos seus endpoints com `role: "client"`.
