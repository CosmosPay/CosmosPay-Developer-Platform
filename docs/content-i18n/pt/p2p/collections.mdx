title: Cobranças
description: Cobre em moeda local e receba stablecoins com uma página de pagamento hospedada, ou integre a rampa de entrada e saída P2P ao seu próprio app.
---

Há duas formas de cobrar pelo mercado P2P. Uma **cobrança** é um link que você compartilha: o
pagador transfere moeda local e você recebe stablecoins na sua carteira. A **rampa integrada** leva o
mesmo fluxo para dentro do seu app, para que seus usuários comprem e vendam.

## Cobranças

Crie uma cobrança com o valor em moeda local e a carteira registrada que recebe os tokens:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/charges \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "currency": "ARS",
    "fiatAmount": "85000",
    "network": "base",
    "token": "USDC",
    "recipient": "ACCOUNT_ID",
    "description": "Order #1042",
    "expiresAt": "2026-12-01T00:00:00Z",
    "multiUse": false
  }'
# → { "id": "…", "url": "https://payments.cosmospay.lat/p2p/…", "status": "open", … }
```

Compartilhe a `url`. Nessa página, o pagador:

1. Vê o valor em moeda local.
2. Informa nome, documento de identidade e email. O comerciante confere se a transferência vem dessa pessoa.
3. Recebe a conta do comerciante e o valor exato, com uma contagem regressiva da janela de pagamento.
4. Transfere pelo banco e toca em **Já transferi**.
5. Acompanha o status ao vivo até o comerciante liberar e então vê o comprovante.

Os tokens chegam à sua carteira `recipient`. Quando a ordem é concluída, a cobrança envia
`P2P_CHARGE_SUCCEEDED`. Uma cobrança tem uma única ordem em andamento por vez; ative `multiUse` para
receber de vários pagadores com o mesmo link. `GET /v1/p2p/charges/{id}` lê a cobrança e `DELETE`
remove uma cobrança que ninguém está pagando.

O painel cria cobranças em **P2P → Cobranças**, com o link e o QR code para compartilhar.

## Rampa integrada

Permita que seus usuários comprem e vendam stablecoins sem sair do seu app. Seu servidor guarda a
chave de API; a carteira do seu usuário assina só o que ela envia.

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

### Comprar

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "BUY", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "fiatAmount": "50000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "recipient": "0xUserWallet",
    "payer": { "name": "Ana Gómez", "document": "20329642330", "email": "ana@example.com" }
  }'
```

A ordem responde `paymentDetails`, a conta do comerciante para esta ordem, e o prazo. Mostre-os ao
seu usuário. Quando ele transferir, informe:

```bash
curl -X POST $API/orders/ORDER_ID/paid -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "reference": "TRX-88421" }'
```

O nome e o documento do pagador são obrigatórios: o comerciante libera apenas uma transferência
dessa pessoa. `POST /v1/p2p/orders/{id}/cancel` cancela antes da transferência, e `/dispute` pede ao
árbitro que decida sobre uma ordem paga que o comerciante não libera.

### Vender

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "SELL", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "tokenAmount": "25" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "seller": "0xUserWallet",
    "payout": { "holderName": "Ana Gómez", "document": "20329642330", "details": { "alias": "ana.gomez.mp" } }
  }'
```

A ordem responde `transactions`: um `approve` e um `openWithDeposit`, não assinados. A carteira do
seu usuário envia as duas, nessa ordem. O comerciante aceita, transfere o dinheiro para a conta de
`payout` e marca a ordem como paga. Depois seu usuário libera com uma transação `release` do
gerador, com o endereço dele como `from`. Se ninguém disputar, a janela de liquidação libera sozinha.

Cada ordem que você abre leva `externalReference` se você enviar um, e os webhooks dela chegam aos
seus endpoints com `role: "client"`.
