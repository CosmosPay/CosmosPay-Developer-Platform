---
title: Início rápido para bots
description: Rode um bot para o seu comerciante P2P. Conceda permissões uma vez, encaminhe suas notificações bancárias ao assistente de correspondência de transferências e libere ordens pagas em segundos.
---

Um bot opera por um comerciante sem ter a chave do comerciante. Ele tem a própria carteira e a
própria chave de API. O comerciante concede permissões a essa carteira no contrato do mercado uma
única vez, e a partir daí o bot assina: atualiza preços, libera as ordens cujo dinheiro chegou e
aceita vendas.

## 1. Conceda as permissões ao bot

As permissões são bits que o contrato verifica em cada chamada que o bot faz por você:

| Permissão | Bit | Permite ao bot |
| --- | --- | --- |
| `open` | `1` | Abrir ordens sobre o seu saldo. |
| `release` | `2` | Liberar suas ordens, o que paga o comprador delas. |
| `trade` | `4` | Aceitar, marcar como paga, cancelar e disputar por você. |
| `withdraw` | `8` | Sacar seu saldo livre para a sua própria carteira, nunca para outra. |

Envie `permissions` como a soma deles, de `0` a `15`, ou como uma lista de nomes: um bot que libera
compras e gerencia vendas precisa de `6`, ou `["release", "trade"]`. A carteira do comerciante
assina a concessão, uma vez por rede:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/transactions \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setOperator", "args": { "operator": "0xBotWallet", "permissions": ["release", "trade"] } }'
```

Uma concessão de `0` revoga o bot. O detalhe da conta lista seus bots por rede em `operators`, cada
endereço com seus bits. O painel faz o mesmo em **P2P → Liquidez**, com uma caixa de seleção por
permissão.

## 2. Dê uma chave de API ao bot

Crie uma chave para o bot e guarde-a no servidor dele, junto com a chave da carteira dele. Nenhuma
das duas chega a um navegador. `p2p:read` basta para ler ordens e as correspondências de
transferências com suas transações `release`; adicione `p2p:write` para atualizar preços e montar
outras transações.

## 3. Libere ordens quando o dinheiro chegar

Encaminhe cada transferência bancária recebida ao assistente de correspondência. Ele responde, da
melhor para a pior, até 10 das suas compras e cobranças em andamento com esse valor e essa moeda
exatos, cada uma com sua transação `release` pronta para assinar. Nada se move até que uma carteira assine.

```ts
const API = 'https://api.cosmospay.lat/cosmos-api/v1/p2p';
const headers = {
  Authorization: `Bearer ${process.env.COSMOS_PAY_API_KEY}`,
  'Content-Type': 'application/json',
};

interface BankTransfer {
  currency: string;       // ISO 4217, e.g. "ARS"
  amount: string;         // local money as received, e.g. "150000.00"
  payerName?: string;     // the sender's name, as the bank reports it
  payerDocument?: string; // the sender's tax id, when the bank reports it
  reference?: string;     // the bank's transfer id
  receivedAt?: string;    // ISO 8601
}

// Called by your bank integration for every incoming transfer.
export async function onBankTransfer(transfer: BankTransfer, wallet: { sendTransaction(tx: object): Promise<string> }) {
  const res = await fetch(`${API}/merchant/transfer-matches`, {
    method: 'POST',
    headers,
    body: JSON.stringify(transfer),
  });
  if (!res.ok) throw new Error(`transfer-matches failed with ${res.status}`);
  const { data } = await res.json();

  const best = data[0];
  // Release on its own only when amount, name and document all match; leave the rest to a person.
  if (!best || best.score < 3) return;

  // The bot's wallet signs and sends; the release permission lets it release the merchant's order.
  const hash = await wallet.sendTransaction(best.transaction);
  console.log(`released order ${best.order.id} (${best.matchedOn.join(', ')}) in ${hash}`);
}
```

Toda correspondência tem o valor e a moeda exatos, então `score` começa em 1. Um nome de pagador
que corresponde soma 1 e um documento que corresponde soma 1: `matchedOn` diz quais. Libere
automaticamente só com 3, quando a transferência vem do pagador indicado na ordem: é essa
verificação que impede que a transferência de um terceiro libere seus tokens.

## 4. Mantenha os preços atualizados

Uma oferta cujo preço é mais antigo que o seu `priceTtlSeconds` não é combinada. Atualize o preço a
partir da sua fonte de cotações em intervalos regulares:

```ts
await fetch(`${API}/offers/${offerId}`, {
  method: 'PATCH',
  headers,
  body: JSON.stringify({ price: '1432.50' }),
});
```

## 5. Ouça os eventos

Inscreva o endpoint do bot nos eventos sobre os quais ele age: `P2P_ORDER_CREATED` para ordens
novas, `P2P_ORDER_PAID` quando um pagador informa uma transferência, `P2P_ORDER_ACCEPTED` para as
vendas que ele precisa pagar e `P2P_ORDER_DISPUTED` para uma pessoa revisar. As entregas ao
comerciante levam `role: "merchant"`; leia a ordem em `GET /v1/p2p/merchant/orders/{id}` para os
dados do pagador ou do beneficiário. Veja [Webhooks](/p2p/webhooks/).

<Callout type="warn" title="Dê a um bot só o que ele precisa">
A chave de um bot é uma chave para a sua liquidez dentro das permissões dele. Deixe `withdraw` de
fora, a menos que o bot faça rebalanceamento, e mantenha o limite por ordem da autorização do
matcher no tamanho com que você opera.
</Callout>
