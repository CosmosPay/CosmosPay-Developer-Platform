---
title: Schnellstart für Bots
description: Betreiben Sie einen Bot für Ihren P2P-Händler. Rechte einmal erteilen, Bankbenachrichtigungen an den Überweisungsabgleich weiterleiten und bezahlte Aufträge in Sekunden freigeben.
---

Ein Bot handelt für einen Händler, ohne den Schlüssel des Händlers zu halten. Er hat seine eigene
Wallet und seinen eigenen API-Schlüssel. Der Händler erteilt dieser Wallet einmal Rechte im Vertrag
des Marktes, danach signiert der Bot: Er aktualisiert Preise, gibt Aufträge frei, deren Geld
eingegangen ist, und nimmt Verkäufe an.

## 1. Dem Bot seine Rechte erteilen

Rechte sind Bits, die der Vertrag bei jedem Aufruf prüft, den der Bot für Sie macht:

| Recht | Bit | Erlaubt dem Bot |
| --- | --- | --- |
| `open` | `1` | Aufträge auf Ihrem Guthaben eröffnen. |
| `release` | `2` | Ihre Aufträge freigeben, was deren Käufer bezahlt. |
| `trade` | `4` | Für Sie annehmen, als bezahlt markieren, stornieren und anfechten. |
| `withdraw` | `8` | Ihr freies Guthaben auf Ihre eigene Wallet abheben, nie anderswohin. |

Übergeben Sie `permissions` als ihre Summe, von `0` bis `15`, oder als Liste von Namen: Ein Bot, der
Käufe freigibt und Verkäufe bearbeitet, braucht `6` oder `["release", "trade"]`. Die Wallet des
Händlers signiert die Erteilung, einmal pro Netzwerk:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/transactions \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setOperator", "args": { "operator": "0xBotWallet", "permissions": ["release", "trade"] } }'
```

Eine Erteilung von `0` widerruft den Bot. Die Kontodetails listen die Bots pro Netzwerk unter
`operators`, jede Adresse mit ihren Bits. Das Dashboard macht dasselbe unter **P2P → Liquidität**,
mit einem Kontrollkästchen pro Recht.

## 2. Dem Bot einen API-Schlüssel geben

Erstellen Sie einen Schlüssel für den Bot und bewahren Sie ihn auf seinem Server auf, neben dem
Schlüssel seiner Wallet. Keiner von beiden gelangt jemals in einen Browser. `p2p:read` genügt, um
Aufträge und die Überweisungstreffer mit ihren `release`-Transaktionen zu lesen; fügen Sie
`p2p:write` hinzu, um Preise zu aktualisieren und weitere Transaktionen zu erstellen.

## 3. Aufträge freigeben, wenn das Geld eingeht

Leiten Sie jede eingehende Banküberweisung an den Überweisungsabgleich weiter. Er liefert, die
besten zuerst, bis zu 10 Ihrer laufenden Käufe und Zahlungsanforderungen über genau diesen Betrag
und diese Währung, jeweils mit der signierbereiten `release`-Transaktion. Nichts bewegt sich, bevor
eine Wallet signiert.

```ts
const API = 'https://api.cosmospay.lat/cosmos-api/v1/p2p';
const headers = {
  Authorization: `Bearer ${process.env.COSMOS_PAY_API_KEY}`,
  'Content-Type': 'application/json',
};

interface BankTransfer {
  currency: string;       // ISO 4217, e.g. "ARS"
  amount: string;         // local money as received, e.g. "150000.00"
  payerName?: string;     // the sender's name, as the bank reports it
  payerDocument?: string; // the sender's tax id, when the bank reports it
  reference?: string;     // the bank's transfer id
  receivedAt?: string;    // ISO 8601
}

// Called by your bank integration for every incoming transfer.
export async function onBankTransfer(transfer: BankTransfer, wallet: { sendTransaction(tx: object): Promise<string> }) {
  const res = await fetch(`${API}/merchant/transfer-matches`, {
    method: 'POST',
    headers,
    body: JSON.stringify(transfer),
  });
  if (!res.ok) throw new Error(`transfer-matches failed with ${res.status}`);
  const { data } = await res.json();

  const best = data[0];
  // Release on its own only when amount, name and document all match; leave the rest to a person.
  if (!best || best.score < 3) return;

  // The bot's wallet signs and sends; the release permission lets it release the merchant's order.
  const hash = await wallet.sendTransaction(best.transaction);
  console.log(`released order ${best.order.id} (${best.matchedOn.join(', ')}) in ${hash}`);
}
```

Jeder Treffer hat den genauen Betrag und die genaue Währung, also beginnt `score` bei 1. Ein
passender Zahlername zählt 1 dazu und ein passendes Dokument noch einmal 1: `matchedOn` nennt
welche. Geben Sie automatisch nur bei 3 frei, wenn die Überweisung vom im Auftrag genannten Zahler
stammt: Genau diese Prüfung verhindert, dass die Überweisung eines Dritten Ihre Token freigibt.

## 4. Preise aktuell halten

Ein Angebot, dessen Preis älter als sein `priceTtlSeconds` ist, wird nicht zugeordnet. Aktualisieren
Sie ihn regelmäßig aus Ihrer Preisquelle:

```ts
await fetch(`${API}/offers/${offerId}`, {
  method: 'PATCH',
  headers,
  body: JSON.stringify({ price: '1432.50' }),
});
```

## 5. Auf die Ereignisse hören

Abonnieren Sie mit dem Endpunkt des Bots die Ereignisse, auf die er reagiert: `P2P_ORDER_CREATED`
für neue Aufträge, `P2P_ORDER_PAID`, wenn ein Zahler eine Überweisung meldet, `P2P_ORDER_ACCEPTED`
für Verkäufe, die er bezahlen muss, und `P2P_ORDER_DISPUTED`, damit eine Person den Fall prüft.
Zustellungen an den Händler tragen `role: "merchant"`; lesen Sie den Auftrag über
`GET /v1/p2p/merchant/orders/{id}` für die Daten des Zahlers oder des Begünstigten. Siehe
[Webhooks](/p2p/webhooks/).

<Callout type="warn" title="Geben Sie einem Bot nur, was er braucht">
Der Schlüssel eines Bots ist ein Schlüssel zu Ihrer Liquidität im Rahmen seiner Rechte. Lassen Sie
`withdraw` weg, außer der Bot gleicht Bestände aus, und halten Sie das Limit pro Auftrag der
Matcher-Autorisierung in der Größe, mit der Sie handeln.
</Callout>
