title: Schnellstart für Händler
description: Stellen Sie dem P2P-Markt Liquidität bereit. Wallet registrieren, Token einzahlen, Cosmos Pay das Zuordnen von Aufträgen erlauben, Zahlungswege hinzufügen, Angebote veröffentlichen und Aufträge bearbeiten.
---

Ein Händler hält Token im Vertrag des Marktes und handelt mit den Personen, die Cosmos Pay seinen
Angeboten zuordnet. Die Token bleiben unter der Kontrolle Ihrer Wallet: Cosmos Pay erstellt jede
Transaktion, und Ihre Wallet signiert sie. Das Dashboard erledigt jeden Schritt dieser Seite unter
**P2P** in der Seitenleiste; hier sehen Sie zusätzlich die API-Aufrufe.

Jede Anfrage trägt Ihren API-Schlüssel mit der Berechtigung `p2p:write`:

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

## 1. Wallet registrieren

Eine Wallet wird mit einer EIP-191-Signatur über eine einmalig gültige Challenge nachgewiesen. Fordern
Sie die Challenge an, signieren Sie ihre `message` mit `personal_sign` in der Wallet und registrieren
Sie dann die Adresse mit der Signatur. Die Challenge gilt 10 Minuten und nur einmal.

```bash
curl -X POST $API/accounts/challenge -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet" }'
# → { "message": "…", "expiresAt": "…" }

curl -X POST $API/accounts -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet", "signature": "0x…", "label": "Treasury", "displayName": "Lumio Exchange" }'
```

Eine Adresse gehört genau einer Organisation. Der `displayName` macht die Wallet zum Händler: Ihn
sehen Käufer und Verkäufer in ihrem Angebot. Ihre Adresse erscheint dort nie.

## 2. Das Händlerprofil verwalten

```bash
curl -X PATCH $API/accounts/ACCOUNT_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "displayName": "Lumio Exchange", "merchantStatus": "PAUSED" }'
```

`merchantStatus` ist `ACTIVE` oder `PAUSED`. Ein pausierter Händler erhält keine neuen Aufträge;
bereits offene Aufträge laufen weiter. Jedes Konto liefert seine `stats`: `completedOrders`,
`cancelledOrders`, `completionRate`, `disputesLost` und `medianReleaseSeconds`.

## 3. Liquidität einzahlen

Einzahlungen fließen in Ihr freies Guthaben im Vertrag. Zwei Transaktionen: ein `approve` über den
genauen Betrag, dann das `deposit`. Beträge stehen in den Basiseinheiten des Tokens: Bei 6
Dezimalstellen sind `"5000000000"` 5.000 USDC. Der Transaktions-Builder liefert jede unsigniert:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "approve", "args": { "token": "USDC", "amount": "5000000000" } }'
# → { "chainId": 8453, "to": "0x…", "data": "0x…", "value": "0", "description": "Allow the P2P market to take exactly 5000 USDC" }
```

Senden Sie sie aus Ihrer Wallet, warten Sie auf die Bestätigung und wiederholen Sie es mit
`"action": "deposit"`. `network` ist eine der IDs, die `GET /v1/p2p/market` listet, und `token` ein
Symbol oder eine Vertragsadresse, die dort aufgeführt ist. `withdraw` nimmt dieselben Argumente und
bringt freie Token jederzeit in Ihre Wallet zurück.

`GET /v1/p2p/accounts/{id}` liest den Vertrag live: pro Netzwerk und Token den freien `amount` und den in
laufenden Aufträgen gesperrten Betrag `locked`, beide in Basiseinheiten, dann die festgelegten
Matcher-Bedingungen und die autorisierten Bots. Der freie Betrag stammt aus dem Vertrag; `locked`
wird aus den über diese API eröffneten Aufträgen berechnet.

## 4. Cosmos Pay mit einem Limit pro Auftrag autorisieren

Der Matcher von Cosmos Pay eröffnet Käufe auf Ihrem Guthaben. Sie legen fest, wie viel ein Auftrag
höchstens sperren darf, in Basiseinheiten:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setMatcher", "args": { "maxPerOrder": "1000000000", "autoSettle": false } }'
```

Ein Limit von `"0"` widerruft die Autorisierung, und ein Konto, dessen `matcher.maxPerOrder` `"0"`
lautet, ist in diesem Netzwerk nicht autorisiert. Der Matcher kann Ihre Token nur bis zu diesem Limit
in Aufträgen sperren. Er kann sie weder abheben noch irgendwohin senden.

<Callout type="warn" title="Automatische Abwicklung ausgeschaltet lassen">
Die automatische Abwicklung erlaubt, einen von Ihnen verkauften Auftrag nach dem
Abwicklungsfenster freizugeben, wenn Sie ihn nicht rechtzeitig anfechten. Ein Liquiditätshändler
braucht sie nie, und die API lehnt sie für eine Wallet mit aktiven Verkaufsangeboten ab. Geben Sie
jeden Auftrag selbst oder über Ihren Bot frei.
</Callout>

## 5. Zahlungswege hinzufügen

Ein Zahlungsweg ist das Konto, auf das Käufer überweisen. Seine Daten werden verschlüsselt
gespeichert und nur dem Käufer des jeweiligen Auftrags angezeigt. Fügen Sie für jeden angebotenen
Weg einen hinzu:

```bash
curl -X POST $API/payment-methods -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "currency": "ARS",
    "rail": "ar_bank_transfer",
    "holderName": "Lumio Exchange SRL",
    "details": { "alias": "lumio.pagos.ars", "cuit": "30714209879" },
    "label": "Main account"
  }'
```

Das Ausweisdokument des Inhabers ist eines der `details`:

| Weg | Währung | `details` |
| --- | --- | --- |
| `ar_bank_transfer` | ARS | Genau eines von `cbu` oder `alias`, und die `cuit` des Inhabers |
| `br_pix` | BRL | `keyType` (`cpf`, `cnpj`, `email`, `phone`, `evp`) und `key` |
| `mx_spei` | MXN | `clabe`, mit ihrer Prüfziffer |
| `co_bank_transfer` | COP | `bank`, `accountType` (`savings`, `checking`), `accountNumber`, `documentType` (`CC`, `CE`, `NIT`, `PP`), `documentNumber` |
| `pe_bank_transfer` | PEN | `cci`, `documentType` (`DNI`, `CE`, `RUC`, `PP`), `documentNumber` |
| `cl_bank_transfer` | CLP | `bank`, `accountType` (`checking`, `vista`, `savings`), `accountNumber`, `rut` |

Der Markt listet die geltenden Wege und ihre Felder unter jeder Währung.

## 6. Angebote veröffentlichen

Ein Angebot sagt, was Sie handeln, zu welchem Preis und innerhalb welcher Grenzen.

```bash
curl -X POST $API/offers -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "side": "SELL_TOKEN",
    "network": "base",
    "token": "USDC",
    "currency": "ARS",
    "rails": ["ar_bank_transfer"],
    "price": "1432.50",
    "priceTtlSeconds": 600,
    "minFiat": "10000",
    "maxFiat": "2500000"
  }'
```

- `SELL_TOKEN` verkauft Token an Kaufende. Jeder seiner `rails` braucht einen aktiven Zahlungsweg.
- `BUY_TOKEN` kauft Token von Verkaufenden und aus den Auszahlungen der Kunden.
- `price` ist Landeswährung pro Token, mit bis zu 6 Dezimalstellen. Der Preis bleibt nach jeder Aktualisierung `priceTtlSeconds` lang zuordenbar, standardmäßig 10 Minuten, zwischen 30 Sekunden und einem Tag; jedes Angebot liefert `priceFresh`. Aktualisieren Sie ihn mit `PATCH /v1/p2p/offers/{id}` oder lassen Sie das Ihren Bot tun.
- `minFiat` und `maxFiat` sind der kleinste und der größte Auftrag in Landeswährung.

Ein Angebot wird zugeordnet, wenn Ihr Händlerstatus `ACTIVE` ist, sein Preis aktuell ist und der
Betrag in seine Grenzen passt. Ein Kauf braucht außerdem ein freies Guthaben und ein Limit pro
Auftrag von mindestens der Tokenmenge; ein Verkauf braucht ein freies Guthaben, das die
Sicherheitsleistung deckt. Unter den infrage kommenden Händlern gewinnt der beste Preis für die
Person, danach die Bilanz: Abschlussquote, Freigabezeit und verlorene Streitfälle.

## 7. Aufträge bearbeiten

`GET /v1/p2p/merchant/orders` listet die Aufträge, die Ihren Wallets zugeordnet wurden, filterbar nach
`status`, `kind` und `address`. Jeder liefert `merchantSide`, Ihre Seite, und was Sie für diese Seite brauchen:
Name und Dokument des `payer` bei einem Kauf, das Konto des `beneficiary` bei einem Verkauf oder einer
Auszahlung.

| Auftrag | Ihre Rolle | Was Sie tun |
| --- | --- | --- |
| Kauf oder Zahlungsanforderung | Sie verkaufen Token | Prüfen Sie, dass die Überweisung vom genannten Zahler stammt, über den genauen Betrag, dann `release`. |
| Verkauf oder Auszahlung | Sie kaufen Token | `accept` vor `acceptDeadline`, überweisen Sie das Geld an den Begünstigten, dann `markPaid` vor `paymentDeadline`. |

Jede Aktion ist eine Transaktion desselben Builders, signiert in Ihrer Wallet:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "release", "args": { "orderId": "ORDER_ID" } }'
```

`cancel` lehnt einen Verkauf oder eine Auszahlung ab, bevor Sie zahlen, und `dispute` bittet die Schiedsstelle, über einen bezahlten Auftrag zu entscheiden: als Käufer eines
Verkaufs oder einer Auszahlung jederzeit, als Verkäufer nur vor der `settleDeadline` des Auftrags. Geben Sie einen Kauf nie frei, bevor das
Geld auf Ihrem Konto ist, und akzeptieren Sie nie eine Überweisung von jemand anderem als dem
genannten Zahler.
