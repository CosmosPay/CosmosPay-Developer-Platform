title: Schnellstart für Händler
description: Stellen Sie dem P2P-Markt Liquidität bereit. Wallet registrieren, Token einzahlen, Cosmos Pay das Zuordnen von Aufträgen erlauben, Zahlungswege hinzufügen, Angebote veröffentlichen und Aufträge bearbeiten.
---

Ein Händler hält Token im Vertrag des Marktes und handelt mit den Personen, die Cosmos Pay seinen
Angeboten zuordnet. Die Token bleiben unter der Kontrolle Ihrer Wallet: Cosmos Pay erstellt jede
Transaktion, und Ihre Wallet signiert sie. Das Dashboard erledigt jeden Schritt dieser Seite unter
**P2P** in der Seitenleiste; hier sehen Sie zusätzlich die API-Aufrufe.

Jede Anfrage trägt Ihren API-Schlüssel mit der Berechtigung `p2p:write`:

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

## 1. Wallet registrieren

Eine Wallet wird mit einer EIP-191-Signatur über eine einmalig gültige Challenge nachgewiesen. Fordern
Sie die Challenge an, signieren Sie ihre `message` mit `personal_sign` in der Wallet und registrieren
Sie sie dann.

```bash
curl -X POST $API/accounts/challenge -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "address": "0xYourWallet" }'
# → { "id": "…", "message": "Cosmos Pay wants you to register this wallet…", "expiresAt": "…" }

curl -X POST $API/accounts -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "challengeId": "…", "address": "0xYourWallet", "signature": "0x…", "label": "Treasury" }'
```

Die Challenge läuft nach wenigen Minuten ab und gilt nur einmal. Eine Adresse gehört genau einer Organisation.

## 2. Als Händler benennen

Der Anzeigename ist das, was Käufer und Verkäufer in ihrem Angebot sehen. Ihre Adresse erscheint nie.

```bash
curl -X PATCH $API/accounts/ACCOUNT_ID -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "merchant": { "displayName": "Lumio Exchange", "status": "ACTIVE" } }'
```

Setzen Sie `status` auf `PAUSED`, um keine neuen Aufträge mehr zu erhalten. Bereits offene Aufträge laufen weiter.

## 3. Liquidität einzahlen

Einzahlungen fließen in Ihr freies Guthaben im Vertrag. Zwei Transaktionen: ein `approve` über den
genauen Betrag, dann das `deposit`. Der Transaktions-Builder liefert jede unsigniert:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "approve", "args": { "token": "USDC", "amount": "5000" } }'
# → { "chainId": 8453, "to": "0x…", "data": "0x…", "value": "0", "description": "…" }
```

Senden Sie sie aus Ihrer Wallet, warten Sie auf die Bestätigung und wiederholen Sie es mit
`"action": "deposit"`. `network` ist eine der IDs, die `GET /v1/p2p/market` listet. `withdraw` nimmt
dieselben Argumente und bringt freie Token jederzeit in Ihre Wallet zurück.

## 4. Cosmos Pay mit einem Limit pro Auftrag autorisieren

Der Matcher von Cosmos Pay eröffnet Käufe auf Ihrem Guthaben. Sie legen fest, wie viel ein Auftrag höchstens sperren darf:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setMatcher", "args": { "maxPerOrder": "1000", "autoSettle": false } }'
```

Ein Limit von `0` widerruft die Autorisierung. Der Matcher kann Ihre Token nur bis zu diesem Limit in
Aufträgen sperren. Er kann sie weder abheben noch irgendwohin senden.

<Callout type="warn" title="Automatische Abwicklung ausgeschaltet lassen">
Die automatische Abwicklung gibt einen von Ihnen verkauften Auftrag nach dem Abwicklungsfenster von
selbst frei. Ein Liquiditätshändler braucht sie nie, und die API lehnt sie für eine Wallet mit aktiven
Verkaufsangeboten ab. Geben Sie jeden Auftrag selbst oder über Ihren Bot frei.
</Callout>

## 5. Zahlungswege hinzufügen

Ein Zahlungsweg ist das Konto, auf das Käufer überweisen. Er wird verschlüsselt gespeichert und nur
dem Käufer des jeweiligen Auftrags angezeigt. Fügen Sie für jeden angebotenen Weg einen hinzu:

```bash
curl -X POST $API/payment-methods -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "rail": "ar_bank_transfer",
    "label": "Main account",
    "holderName": "Lumio Exchange SRL",
    "document": "30714209879",
    "details": { "cbu": "0170099222000001234561", "alias": "lumio.pagos.ars" }
  }'
```

| Weg | Währung | `details` | `document` des Inhabers |
| --- | --- | --- | --- |
| `ar_bank_transfer` | ARS | `cbu` mit seinen Prüfziffern, oder `alias` | CUIT oder CUIL |
| `br_pix` | BRL | `pixKeyType` (`cpf`, `cnpj`, `email`, `phone`, `evp`) und `pixKey` | CPF oder CNPJ |
| `mx_spei` | MXN | `clabe` mit ihrer Prüfziffer | RFC, optional |
| `co_bank_transfer` | COP | `bank`, `accountType` (`savings`, `checking`), `accountNumber` | NIT oder Ausweisnummer |
| `pe_bank_transfer` | PEN | `cci` | DNI oder RUC |
| `cl_bank_transfer` | CLP | `bank`, `accountType` (`checking`, `vista`, `savings`), `accountNumber` | RUT |

Der Markt listet die geltenden Wege und ihre Felder.

## 6. Angebote veröffentlichen

Ein Angebot sagt, was Sie handeln, zu welchem Preis und innerhalb welcher Grenzen.

```bash
curl -X POST $API/offers -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "accountId": "ACCOUNT_ID",
    "side": "SELL_TOKEN",
    "network": "base",
    "token": "USDC",
    "currency": "ARS",
    "rails": ["ar_bank_transfer"],
    "price": "1432.50",
    "priceTtlSeconds": 900,
    "minFiat": "10000",
    "maxFiat": "2500000"
  }'
```

- `SELL_TOKEN` verkauft Token an Kaufende. Jeder seiner `rails` braucht einen aktiven Zahlungsweg.
- `BUY_TOKEN` kauft Token von Verkaufenden und aus den Auszahlungen der Kunden.
- `price` ist Landeswährung pro Token. Ein Preis, der älter als `priceTtlSeconds` ist, wird nicht zugeordnet: Aktualisieren Sie ihn mit `PATCH /v1/p2p/offers/{id}` oder lassen Sie das Ihren Bot tun.

Ein Angebot wird zugeordnet, wenn Ihr Händlerstatus `ACTIVE` ist, sein Preis aktuell ist und der
Betrag in seine Grenzen passt. Ein Kauf braucht außerdem ein freies Guthaben und ein Limit pro
Auftrag von mindestens der Tokenmenge; ein Verkauf braucht ein freies Guthaben, das die
Sicherheitsleistung deckt. Unter den infrage kommenden Händlern gewinnt der beste Preis für die
Person, danach die Bilanz: Abschlussquote, Freigabezeit und verlorene Streitfälle.

## 7. Aufträge bearbeiten

`GET /v1/p2p/merchant/orders` listet die Aufträge, die Ihren Wallets zugeordnet wurden. Jeder zeigt,
was Sie für Ihre Seite brauchen, und nichts darüber hinaus.

| Auftrag | Ihre Rolle | Was Sie tun |
| --- | --- | --- |
| Kauf oder Zahlungsanforderung | Sie verkaufen Token | Prüfen Sie, dass die Überweisung vom im Auftrag genannten Zahler stammt, über den genauen Betrag, dann `release`. |
| Verkauf oder Auszahlung | Sie kaufen Token | `accept` vor Ablauf der Annahmefrist, überweisen Sie das Geld auf das angezeigte Konto, dann `markPaid`. |

Jede Aktion ist eine Transaktion desselben Builders, signiert in Ihrer Wallet:

```bash
curl -X POST $API/transactions -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "release", "args": { "orderId": "ORDER_ID" } }'
```

`cancel` lehnt einen Verkauf ab, bevor Sie zahlen, und `dispute` bittet die Schiedsstelle, über einen
bezahlten Auftrag zu entscheiden. Geben Sie einen Kauf nie frei, bevor das Geld auf Ihrem Konto ist,
und akzeptieren Sie nie eine Überweisung von jemand anderem als dem genannten Zahler.
