---
title: Payouts
description: Pay up to 100 bank accounts in local money from your stablecoin balance. Each payout is matched to a merchant who pays the beneficiary before your tokens are released.
---

A payout batch sends local money to bank accounts and pays for it with stablecoins you hold in the
market contract. Each item becomes an order: a merchant buys your tokens, pays the beneficiary
and marks the order paid, and you release. Your tokens leave your balance only for a merchant
that has paid.

## Before the first batch

1. **Register the wallet** that pays. See [Merchant quick start](/p2p/merchants/).
2. **Deposit** the tokens the batch needs into the contract.
3. **Authorise Cosmos Pay's matcher** on that network with `setMatcher`, with a per-order cap at least as large as your biggest payout. Keep `autoSettle` off to release each payout yourself, or turn it on to let a paid payout be released after the settle window.

## Send a batch

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/payouts \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "network": "base",
    "token": "USDC",
    "accountId": "ACCOUNT_ID",
    "items": [
      {
        "currency": "ARS",
        "fiatAmount": "150000",
        "rail": "ar_bank_transfer",
        "beneficiary": {
          "holderName": "Ana Gómez",
          "document": "20329642330",
          "details": { "cbu": "0170099222000001234561", "cuit": "20329642330" }
        },
        "externalReference": "payroll-2026-11-ana"
      }
    ]
  }'
```

A batch holds 1 to 100 items. `accountId` is the wallet that pays, optional when you have exactly
one. Each beneficiary has a name, an identity document of 4 to 20 characters and the rail's
`details`, checked as a payment method's: see the rails table in
[Merchant quick start](/p2p/merchants/).

## What happens to each item

1. Cosmos Pay matches the item to a merchant that buys tokens on that rail and opens the order on your balance. The merchant locks a bond of 10%.
2. The merchant accepts, transfers the money to the beneficiary and marks the order paid.
3. You check the payment and release: a `release` transaction from the builder, signed by your wallet or by your bot with the `release` permission.

An item no merchant can take right now lands in `failedItems` with its `reason`; your tokens never
moved for it. A merchant that does not accept or pay in time lets the deadline return your tokens.

## Batch status

`GET /v1/p2p/payouts/{id}` answers the batch with its `orders`, its `failedItems` and `itemCount`.
The list, `GET /v1/p2p/payouts`, answers each batch without its orders: read a batch by id for them.

| Status | Meaning |
| --- | --- |
| `processing` | At least one order is still live. |
| `completed` | Every order completed. |
| `partially_completed` | Every order ended and some did not complete. |
| `failed` | No order completed. |

`P2P_PAYOUT_BATCH_COMPLETED` fires when every order of a batch has ended, and each order sends its
own events.

## Upload a CSV from the dashboard

**P2P → Payouts** takes a CSV file with one beneficiary per row and checks every row before
anything is sent: the rail's account format and check digits, the document, the amount and
repeated references. Rows with a problem show it next to them. Columns, by header name in any
order:

| Column | Content |
| --- | --- |
| `currency` | ISO 4217 code, for example `ARS` |
| `amount` | Amount in local money |
| `rail` | `ar_bank_transfer`, `br_pix`, `mx_spei`, `co_bank_transfer`, `pe_bank_transfer` or `cl_bank_transfer` |
| `holderName` | The beneficiary's name |
| `document` | The beneficiary's ID document |
| `cbu`, `alias`, `cuit` | Argentina |
| `keyType`, `key` | Brazil |
| `clabe` | Mexico |
| `bank`, `accountType`, `accountNumber` | Colombia and Chile |
| `documentType`, `documentNumber` | Colombia and Peru |
| `cci` | Peru |
| `rut` | Chile |
| `reference` | Your own reference, unique in the file |

Commas or semicolons both work. The page offers a template with one row per rail.
