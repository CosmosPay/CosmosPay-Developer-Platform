---
title: P2P webhooks
description: The events P2P orders, charges and payouts send, who receives each one and what its payload holds.
---

P2P events go through the same webhook endpoints as every Cosmos Pay event, signed the same way.
Register an endpoint in the dashboard under **Webhooks**, or with the API, and pick the events
below.

## Events

| Event | Sent when |
| --- | --- |
| `P2P_ORDER_CREATED` | An order opened on-chain. |
| `P2P_ORDER_ACCEPTED` | A merchant accepted a sale or a payout and locked its bond. Purchases and charges skip this step. |
| `P2P_ORDER_PAID` | The buyer side marked the order paid. |
| `P2P_ORDER_COMPLETED` | The seller released. The buyer received the tokens. |
| `P2P_ORDER_CANCELLED` | The order was cancelled. The tokens went back to the seller. |
| `P2P_ORDER_EXPIRED` | A deadline passed. The tokens went back to the seller. |
| `P2P_ORDER_DISPUTED` | One side opened a dispute. |
| `P2P_ORDER_RESOLVED` | The arbiter decided the dispute. |
| `P2P_ORDER_FAILED` | The order never opened. |
| `P2P_CHARGE_SUCCEEDED` | An order paying a charge completed. A multi-use charge sends one per paying order. |
| `P2P_PAYOUT_BATCH_COMPLETED` | Every order of a payout batch ended. |

Completed, cancelled, expired, resolved and failed orders, succeeded charges and finished batches
are final: no further event follows them.

## Who receives them

An order's events reach two parties: the client that opened it and the merchant it was matched to,
when they are different organizations. `data.role` says which one you are, and each receives only
its own view of the order.

| `data.role` | The payload holds | It never holds |
| --- | --- | --- |
| `client` | The order's amounts, addresses, deadlines, transaction hashes and status, the merchant's display name and record, and your own `externalReference`, `chargeId` and `payoutBatchId` | Payment details, the payer's identity or a beneficiary's account |
| `merchant` | The order's amounts, addresses, deadlines, transaction hashes and status, with your `merchantAccountId` and `merchantSide` | Payment details, the payer's identity, a beneficiary's account or the client's own references |

Read the order from the API for what a webhook leaves out: `GET /v1/p2p/orders/{id}` for a client,
`GET /v1/p2p/merchant/orders/{id}` for a merchant.

Use `id` to process each event once. Read the order again with the API before you act on money:
an event tells you something changed, the order tells you what it is now.

## Verify the signature

Every delivery carries `X-Cosmos-Signature: t=<unix seconds>,v1=<hex>`, an HMAC-SHA256 of
`<t>.<raw body>` with your endpoint's secret. Verify it on the raw body before you trust the event.
The SDK does it for you: see [Webhooks](/sdk/server/webhooks/).
