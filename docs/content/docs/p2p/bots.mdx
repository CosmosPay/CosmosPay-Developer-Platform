---
title: Bot quick start
description: Run a bot for your P2P merchant. Grant it permissions once, forward your bank notifications to the transfer-matches helper and release paid orders in seconds.
---

A bot trades for a merchant without holding the merchant's key. It has its own wallet and its own
API key. The merchant grants that wallet permissions on the market contract once, and the bot
signs from then on: it refreshes prices, releases orders whose money arrived and accepts sales.

## 1. Grant the bot its permissions

Permissions are bits the contract checks on every call the bot makes for you:

| Permission | Bit | Lets the bot |
| --- | --- | --- |
| `open` | `1` | Open orders on your balance. |
| `release` | `2` | Release your orders, which pays their buyer. |
| `trade` | `4` | Accept, mark paid, cancel and dispute for you. |
| `withdraw` | `8` | Withdraw your free balance to your own wallet, never elsewhere. |

Pass `permissions` as their sum, from `0` to `15`, or as a list of names: a bot that releases
purchases and handles sales needs `6`, or `["release", "trade"]`. The merchant's wallet signs the
grant, once per network:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/transactions \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{ "network": "base", "from": "ACCOUNT_ID", "action": "setOperator", "args": { "operator": "0xBotWallet", "permissions": ["release", "trade"] } }'
```

A grant of `0` revokes the bot. The account's detail lists its bots per network under `operators`,
each address with its bits. The dashboard does the same under **P2P → Liquidity**, with a
checkbox per permission.

## 2. Give the bot an API key

Create a key for the bot and keep it on the bot's server, next to its wallet key. Neither ever
reaches a browser. `p2p:read` is enough to read orders and the transfer matches with their
`release` transactions; add `p2p:write` to refresh prices and build other transactions.

## 3. Release orders when the money arrives

Forward each incoming bank transfer to the transfer-matches helper. It answers, best first, up to
10 of your live purchases and charges for that exact amount and currency, each with its `release`
transaction ready to sign. Nothing moves until a wallet signs.

```ts
const API = 'https://api.cosmospay.lat/cosmos-api/v1/p2p';
const headers = {
  Authorization: `Bearer ${process.env.COSMOS_PAY_API_KEY}`,
  'Content-Type': 'application/json',
};

interface BankTransfer {
  currency: string;       // ISO 4217, e.g. "ARS"
  amount: string;         // local money as received, e.g. "150000.00"
  payerName?: string;     // the sender's name, as the bank reports it
  payerDocument?: string; // the sender's tax id, when the bank reports it
  reference?: string;     // the bank's transfer id
  receivedAt?: string;    // ISO 8601
}

// Called by your bank integration for every incoming transfer.
export async function onBankTransfer(transfer: BankTransfer, wallet: { sendTransaction(tx: object): Promise<string> }) {
  const res = await fetch(`${API}/merchant/transfer-matches`, {
    method: 'POST',
    headers,
    body: JSON.stringify(transfer),
  });
  if (!res.ok) throw new Error(`transfer-matches failed with ${res.status}`);
  const { data } = await res.json();

  const best = data[0];
  // Release on its own only when amount, name and document all match; leave the rest to a person.
  if (!best || best.score < 3) return;

  // The bot's wallet signs and sends; the release permission lets it release the merchant's order.
  const hash = await wallet.sendTransaction(best.transaction);
  console.log(`released order ${best.order.id} (${best.matchedOn.join(', ')}) in ${hash}`);
}
```

Every match has the exact amount and currency, so `score` starts at 1. A matching payer name adds
1 and a matching document adds 1: `matchedOn` lists which. Release automatically only at 3, when
the transfer comes from the payer the order names: that is the check that keeps a third party's
transfer from releasing your tokens.

## 4. Keep prices fresh

An offer whose price is older than its `priceTtlSeconds` is not matched. Refresh it from your
pricing source on a timer:

```ts
await fetch(`${API}/offers/${offerId}`, {
  method: 'PATCH',
  headers,
  body: JSON.stringify({ price: '1432.50' }),
});
```

## 5. Listen to the events

Subscribe the bot's endpoint to the events it acts on: `P2P_ORDER_CREATED` for new orders,
`P2P_ORDER_PAID` when a payer reports a transfer, `P2P_ORDER_ACCEPTED` for sales it must pay, and
`P2P_ORDER_DISPUTED` for a person to review. Merchant deliveries carry `role: "merchant"`; read the
order from `GET /v1/p2p/merchant/orders/{id}` for the payer or beneficiary details. See
[Webhooks](/p2p/webhooks/).

<Callout type="warn" title="Give a bot only what it needs">
A bot's key is a key to your liquidity within its permissions. Leave out `withdraw` unless the bot
rebalances, and keep the per-order cap of your matcher authorisation at the size you trade.
</Callout>
