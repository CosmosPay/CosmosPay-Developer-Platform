Two ways to collect through the P2P market. A **charge** is a link you share: the payer transfers
local money and you receive stablecoins in your wallet. The **embedded ramp** puts the same flow
inside your own app, for your users to buy and sell.

## Charges

Create a charge with the amount in local money and the registered wallet that receives the tokens:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/charges \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "currency": "ARS",
    "fiatAmount": "85000",
    "network": "base",
    "token": "USDC",
    "recipient": "ACCOUNT_ID",
    "description": "Order #1042",
    "expiresAt": "2026-12-01T00:00:00Z",
    "multiUse": false
  }'
# → { "id": "…", "url": "https://payments.cosmospay.lat/p2p/…", "status": "open", "recipientAddress": "0x…", "paidCount": 0, … }
```

`recipient` is one of your account ids. A charge expires 24 hours after it is created unless
`expiresAt` says otherwise, at most 30 days ahead.

Share the `url` as a link; it opens the payer page. On that page the payer:

1. Sees the amount in local money.
2. Enters their name, ID document and email. The merchant checks the transfer comes from that person.
3. Gets the merchant's account and the exact amount, with a countdown for the payment window.
4. Transfers from their bank and presses **I transferred**.
5. Follows the status live until the merchant releases, then sees the receipt.

The tokens go to the recipient wallet. Each time a paying order completes, the charge sends
`P2P_CHARGE_SUCCEEDED` and counts it in `paidCount`. A charge takes one payer at a time; set
`multiUse` to collect from many payers on the same link. `status` is `open`, `paid`, `cancelled` or
`expired`. `DELETE /v1/p2p/charges/{id}` cancels an open charge: no new payer can start, and an
order already under way still pays the recipient when it completes. Every charge route is in the
[charges and payouts reference](/api/p2p-collections/).

The hosted page calls the keyless routes of the [P2P checkout API](/api/p2p-checkout/): it reads the
charge, starts paying it with `POST /v1/p2p-checkout/charges/{id}/orders` and the payer's rail, name,
document and email, and follows the order with the `payerToken` that answer carries, sent as
`X-Payer-Token`.

## Embedded ramp

Let your own users buy and sell stablecoins without leaving your app. Your server holds the API
key; your user's wallet signs only what it sends.

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

### Buy

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "BUY", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "fiatAmount": "50000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "recipient": "0xUserWallet",
    "payer": { "name": "Ana Gómez", "document": "20329642330" },
    "externalReference": "order-881"
  }'
```

The order answers `paymentDetails`, the merchant's account for this order, and `paymentDeadline`.
Show them to your user. Once they transfer, report it:

```bash
curl -X POST $API/orders/ORDER_ID/paid -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "reference": "TRX-88421" }'
```

The payer's name and document are required: the merchant releases only a transfer from that
person. `POST /v1/p2p/orders/{id}/cancel` cancels before the transfer, and `/dispute` asks the
arbiter to decide a paid order the merchant does not release.

To charge your own fee, pass `integratorFeeBps` and `integratorAccountId` on the quote. The fee is
taken from what the buyer receives and paid on-chain to that wallet.

### Sell

The token amount of a sale is in base units: `"25000000"` is 25 USDC.

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "SELL", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "tokenAmount": "25000000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "seller": "0xUserWallet",
    "beneficiary": { "holderName": "Ana Gómez", "document": "20329642330", "details": { "alias": "ana.gomez.mp", "cuit": "20329642330" } }
  }'
```

The order answers `transactions`: an `approve` and an `openWithDeposit`, unsigned. Your user's
wallet sends both, in that order. The merchant accepts, transfers the money to the `beneficiary`
account and marks the order paid. Your user then releases with a `release` transaction from the
builder, with their address as `from`. If nobody disputes the order, it can be released by anyone
once the settle window has passed.

`GET /v1/p2p/orders` lists the orders you opened, filtered by `status` and `kind`. Their webhooks
reach your endpoints with `role: "client"`.
