title: Collections
description: Charge in local money and receive stablecoins with a hosted payer page, or embed the P2P on-ramp and off-ramp in your own app.
---

Two ways to collect through the P2P market. A **charge** is a link you share: the payer transfers
local money and you receive stablecoins in your wallet. The **embedded ramp** puts the same flow
inside your own app, for your users to buy and sell.

## Charges

Create a charge with the amount in local money and the registered wallet that receives the tokens:

```bash
curl -X POST https://api.cosmospay.lat/cosmos-api/v1/p2p/charges \
  -H "Authorization: Bearer $COSMOS_PAY_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "currency": "ARS",
    "fiatAmount": "85000",
    "network": "base",
    "token": "USDC",
    "recipient": "ACCOUNT_ID",
    "description": "Order #1042",
    "expiresAt": "2026-12-01T00:00:00Z",
    "multiUse": false
  }'
# → { "id": "…", "url": "https://payments.cosmospay.lat/p2p/…", "status": "open", … }
```

Share the `url`. On that page the payer:

1. Sees the amount in local money.
2. Enters their name, ID document and email. The merchant checks the transfer comes from that person.
3. Gets the merchant's account and the exact amount, with a countdown for the payment window.
4. Transfers from their bank and presses **I transferred**.
5. Follows the status live until the merchant releases, then sees the receipt.

The tokens go to your `recipient` wallet. When the order completes, the charge sends
`P2P_CHARGE_SUCCEEDED`. A charge has one live order at a time; set `multiUse` to collect from many
payers on the same link. `GET /v1/p2p/charges/{id}` reads it and `DELETE` removes a charge nobody
is paying.

The dashboard creates charges under **P2P → Charges**, with the link and its QR code to share.

## Embedded ramp

Let your own users buy and sell stablecoins without leaving your app. Your server holds the API
key; your user's wallet signs only what it sends.

```bash
export API=https://api.cosmospay.lat/cosmos-api/v1/p2p
export AUTH="Authorization: Bearer $COSMOS_PAY_API_KEY"
```

### Buy

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "BUY", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "fiatAmount": "50000" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "recipient": "0xUserWallet",
    "payer": { "name": "Ana Gómez", "document": "20329642330", "email": "ana@example.com" }
  }'
```

The order answers `paymentDetails`, the merchant's account for this order, and the deadline. Show
them to your user. Once they transfer, report it:

```bash
curl -X POST $API/orders/ORDER_ID/paid -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "reference": "TRX-88421" }'
```

The payer's name and document are required: the merchant releases only a transfer from that
person. `POST /v1/p2p/orders/{id}/cancel` cancels before the transfer, and `/dispute` asks the
arbiter to decide a paid order the merchant does not release.

### Sell

```bash
curl -X POST $API/quotes -H "$AUTH" -H "Content-Type: application/json" \
  -d '{ "side": "SELL", "network": "base", "token": "USDC", "currency": "ARS", "rail": "ar_bank_transfer", "tokenAmount": "25" }'

curl -X POST $API/orders -H "$AUTH" -H "Content-Type: application/json" \
  -d '{
    "quoteId": "QUOTE_ID",
    "seller": "0xUserWallet",
    "payout": { "holderName": "Ana Gómez", "document": "20329642330", "details": { "alias": "ana.gomez.mp" } }
  }'
```

The order answers `transactions`: an `approve` and an `openWithDeposit`, unsigned. Your user's
wallet sends both, in that order. The merchant accepts, transfers the money to the account in
`payout` and marks the order paid. Your user then releases with a `release` transaction from the
builder, `from` being their address. If nobody disputes, the settle window releases it on its own.

Every order you open carries `externalReference` if you pass one, and its webhooks reach your
endpoints with `role: "client"`.
